# Аудит безопасности — пункт 5

Дата: 15 октября 2026. Исходная версия: `9dda85f`. Аудит покрывает секреты в доступной Git-истории/текущих файлах и известные уязвимости npm-зависимостей. Это не полный penetration test приложения или аудит аккаунтов Vercel/Supabase.

## Секреты

- После `git fetch --all --tags` репозиторий не shallow; Gitleaks **8.30.1** проверил все **21 доступный commit** через `--all --full-history`, без baseline, с `--redact=100`. Файлы и история анализировались локально; их содержимое не отправлялось внешнему сканеру.
- Исходное срабатывание ровно одно: закомментированный невалидный пример `re_123456789` в `.env.example`, commit `58fb7d5`, строка 13. Это пример, не действующий ключ. В `.gitleaksignore` указан только точный fingerprint этого исторического срабатывания; общих исключений для файлов, типов ключей или всей истории нет. Сам пример заменён текстовым placeholder. После review — **0 необработанных находок**.
- Отдельно скопированы только tracked/unignored файлы в игнорируемую QA-папку; Gitleaks directory scan — **0 находок**. Локальная `.env`, node_modules и Chrome profiles в копию не включались.
- `npm run check:secret-exposure` дополнительно ищет реальные настроенные локальные секреты длиной ≥24 символов, буквально и в Base64: во всех reachable Git blobs, текущих tracked/unignored файлах и `.next/static`. Первичная проверка: один не-example секрет, 293 Git blobs, 36 клиентских assets, **0 совпадений**. Значения и их хеши не печатаются. Dev-placeholder со специальным префиксом не выдаётся за действующий ключ.
- `.gitignore` теперь закрывает все `.env*`, кроме `.env.example`, включая `.env.production` и `.env.development`. Изменения истории, force push, отзыв ключей не потребовались: действующий секрет в проверенных данных не найден.

Ограничения: Gitleaks использует шаблоны, exact scan видит лишь локально доступные секреты; это не гарантия отсутствия всех неизвестных/зашифрованных значений. Недоступные удалённые refs, GitHub caches, reflogs других клонов и секреты внешних аккаунтов не проверялись.

## Зависимости и исправления

Первоначальный `npm audit`: **11** уязвимых узлов (3 critical / 5 high / 3 moderate; это число пакетов/цепочек npm, не число независимых CVE).

| Изменение | Причина |
|---|---|
| Next.js 14.2.35 → **15.5.28** | Поддерживаемая исправленная ветка; [официальный security update 14 октября](https://nextjs.org/blog/nextjs-security-update-october-14-2026) |
| eslint-config-next → **15.5.28** | Согласование с framework; правила сохранены |
| Vitest 2.1.9 → **4.1.11** | Устранение уязвимых mocker/tinypool/Vite/esbuild цепочек |
| PostCSS → **8.5.30**, точный override | Устранение известных уязвимостей старого транзитивного PostCSS в Next; версия зафиксирована в lock |
| Node **24.x** | Воспроизводимая совместимая версия для Next/Vitest/Vite; используется в CI |

`npm run audit:production` (`npm audit --omit=dev --audit-level=low`) — **0 уязвимостей** после обновлений.

**Полный аудит не чистый:** остаются **5 high** узлов одной dev-цепочки `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`. [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) — исчерпание стека при глубоко вложенном glob; исправленной версии `braces` пока нет. Пакеты отмечены `dev: true` в lock, не входят в production runtime; линтер работает с локальными шаблонами путей, не с пользовательским вводом сайта. Риск остаётся при линтинге/сборке недоверенного кода. Не следует запускать чужие изменения с production-секретами. Это технически ограниченное исключение, а не утверждение об отсутствии проблемы.

`npm run audit:dependencies` показывает все пять находок и допускает только эту точную advisory/цепочку **только для dev-пакетов до 2026-11-15**. Любая новая advisory, production exposure, ошибка/недоступность audit или истечение review дают ненулевой exit. Обычный `npm audit` по-прежнему возвращает 1; вывод не подменяется нулём. После появления исправления/смены dev-инструмента нужно удалить исключение.

## Совместимость и автоматизация

- Next.js 15: landing/report ожидают Promise `searchParams`; серверный render тестируется асинхронно. Внутренние ссылки report/privacy заменены на Next Link без изменения подписей. Финансовый dataset/формулы и серверные API-контракты не менялись.
- Vitest использует явный classic JSX transform OXC и `tests/**/*.test.ts`; QA-копии из tmp не участвуют в подсчёте тестов. TypeScript также исключает tmp/output. `npm run lint` использует ESLint CLI вместо deprecated `next lint`, без отключения существующих правил.
- Добавлены проверки секретов, включая исторический удалённый blob и Base64 в клиентском asset, и проверки audit gate: известный dev advisory, новый advisory, production exposure и недоступность аудита.
- GitHub Actions: `security.yml`, push/PR/ручной запуск/понедельник 06:25 UTC. Read-only permissions, checkout без сохранения credentials, действия зафиксированы на проверенных SHA. Gitleaks 8.30.1 скачивается из официального release и проверяется фиксированным SHA256. Pipeline не получает production-секреты и не публикует отчёты с их значениями. Первый реальный CI run будет проверен после push; один YAML-файл не считается доказательством выполнения CI.
