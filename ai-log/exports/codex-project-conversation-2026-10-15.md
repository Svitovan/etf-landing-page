Для этого проекта схема такая: **GitHub → Vercel запускает сайт и API → Supabase хранит контакты и аналитику**. Код подключения уже есть.

**1. Создай проект Supabase**

1. Открой [Supabase Dashboard](https://supabase.com/dashboard) → **New project**.
2. Выбери организацию, название, например `etf-prehled`, европейский регион и сохрани пароль БД.
3. После создания открой **SQL Editor → New query**.
4. Вставь содержимое [миграции проекта](</[REDACTED:local-path]>) и нажми **Run**.

В **Table Editor** должны появиться пять таблиц: `leads`, `lead_submissions`, `analytics_sessions`, `analytics_events`, `rate_limit_buckets`. Миграция уже включает RLS. [Документация таблиц](https://supabase.com/docs/guides/database/tables).

Затем возьми:

- **Project URL** — через кнопку **Connect**.
- **Secret key** вида `sb_secret_…` — **Settings → API Keys**.

Нужен именно серверный secret key. **Не присылай его в чат и не добавляй в GitHub.** [Документация ключей](https://supabase.com/docs/guides/getting-started/api-keys).

**2. Подключи GitHub к Vercel**

Открой [Vercel](https://vercel.com/new), войди через GitHub и импортируй `Svitovan/etf-landing-page`.

Настройки:

| Поле | Значение |
|---|---|
| Framework Preset | Next.js |
| Root Directory | Корень репозитория |
| Build Command | `npm run build` |
| Output Directory | По умолчанию |
| Production Branch | `master` |

Vercel будет собирать опубликованные в GitHub изменения. Сейчас у тебя есть локальные изменения интерфейса — они попадут на сайт после коммита и push. [Подключение GitHub](https://vercel.com/docs/git/vercel-for-github).

**3. Добавь переменные окружения в Vercel**

При импорте либо в **Project → Settings → Environment Variables**:

| Имя | Значение |
|---|---|
| `SUPABASE_URL` | URL проекта Supabase |
| `SUPABASE_SECRET_KEY` | `sb_secret_…` |
| `RATE_LIMIT_SECRET` | Случайный секрет, минимум 32 байта |
| `DATASET_VERSION` | `2026-10-11` |
| `APP_ORIGIN` | Итоговый адрес сайта `https://….vercel.app` |

Для первого размещения выбери окружение **Production**. Секретные переменные не должны иметь префикс `NEXT_PUBLIC_`.

Нажми **Deploy**. Если переменные добавлены после размещения, сделай **Redeploy**: изменение переменных применяется к новым deployment. [Переменные Vercel](https://vercel.com/docs/environment-variables).

`APP_ORIGIN` предусмотрен конфигурацией, но текущий код его ещё не использует для проверки запросов. `ANALYTICS_SESSION_SECRET` тоже пока не используется.

**4. Подключи локальную разработку**

В корне проекта создай `.env.local` по образцу [.env.example](</[REDACTED:local-path]>) и заполни те же переменные. Для локального адреса:

```dotenv
APP_ORIGIN=http://localhost:3000
```

Перезапусти `npm run dev`. `.env.local` уже исключён из Git.

**5. Проверь настоящее сохранение**

На опубликованном сайте отправь тестовую заявку, затем открой Supabase **Table Editor**:

- В `lead_submissions` появилась связанная заявка.
- После отправки открывается материал.

**Одного сообщения об успехе недостаточно:** текущий backend может показать успех даже без подключения БД, используя память процесса. Подключение сервисов позволит проверить хранение, но ранее найденные ошибки атомарности и аналитики ещё требуют исправления.
